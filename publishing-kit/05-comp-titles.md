# Comparable Titles

| Title & Author | Angle/Audience | How A-Dev differs |
| --- | --- | --- |
| Clean Code — Robert C. Martin | Software craftsmanship; manual coding discipline | Moves discipline into baseline governance for AI outputs; orchestration + flags/50-50 over line-by-line craft |
| Clean Architecture — Robert C. Martin | Architecture patterns; team-oriented | Frugal, solo-friendly constraints (no heavy middleware, SSR-first); governance-first instead of framework-heavy layering |
| The Pragmatic Programmer — Hunt/Thomas | Generalist dev wisdom; craftsmen | Embraces the knowledge gap with AI; codifies prompts + traceability as part of practice |
| The Lean Startup — Eric Ries | Build-measure-learn for founders | “Validation at origin”: quality/security baked in via 50/50 + Live Alpha, not just market iteration |
| Accelerate — Forsgren/Humble/Kim | DevOps metrics for orgs | Solo/SME view with simple machines; emphasizes evidence timelines and flags instead of large-platform tooling |
| Team Topologies — Skelton/Pais | Team design for flow | Treats AI + solo architect as the team; governance/baseline replaces org topology |
| Shape Up — Basecamp | Product cycles; small teams | 1–2h atomic loops with AI; flags and baselines keep scope tight and reversible |
| Prompt engineering handbooks (various) | How to write prompts | A-Dev = prompt + baseline + evidence; focuses on systems to validate prompts, not just wording |
