# 50/50 Broad Quality Cycle Checklist

Treat creation and verification as one continuous movement. The 50/50 principle is a symbol of balanced attention, not an exact time split or universal iteration length.

- [ ] Definition written (scope in/out, persona, success behavior)
- [ ] Baseline guardrails linked (security, frugality, UI consistency)
- [ ] Prompt ready with context + constraints + quality gates
- [ ] Progressive-delivery control defined when the change needs one
- [ ] Focused build, analysis, and tests executed for the affected surface
- [ ] User or system walkthrough completed in the relevant configuration
- [ ] Evidence captured (commit/CI links, decision log entry)
- [ ] Baseline updated if anything failed or changed
- [ ] Rollback or containment path verified when relevant
