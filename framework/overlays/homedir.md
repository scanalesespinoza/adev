# Overlay: Homedir

**Applies when** work happens in [Homedir](https://github.com/scanalesespinoza/homedir), A-Dev's proving ground, or when A-Dev material cites evidence from it. Homedir is the proving ground; A-Dev is the transferable system.

## Operating in Homedir

1. Keep the [shared handoff workspace](multi-agent-handoff.md) current.
2. After a merge, verify public-site behavior. The routes `/`, `/comunidad`, `/eventos`, and `/proyectos` are valid project-level checks, not universal A-Dev requirements.
3. The [web product](web-product.md), [marketing automation](marketing-automation.md), and [platform operations](platform-operations.md) overlays apply where their scope matches.

## Citing Homedir evidence

1. Homedir is the canonical reference repository for A-Dev operational evidence and reference cases. Do not substitute a similar name, an execution transcript, or an unsourced summary for the repository source.
2. Every factual claim, evidence record, or case-study statement derived from Homedir links directly to the relevant artifact: a file, commit, pull request, issue, release, or workflow run. Link to the repository root only when no more specific durable artifact exists, and state that limitation.
3. Record the observed commit, tag, or date when a mutable artifact supports a claim. Never infer a result, metric, causal relationship, or adoption signal that the linked artifact does not establish; label unsupported material as a proposal or gap.
4. Extract the transferable principle. Project-specific detail must not replace doctrine.
